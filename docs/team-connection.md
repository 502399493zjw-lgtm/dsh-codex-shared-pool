# 云端 Team 连接与恢复

从 `0.1.5` 开始，在没有配置 `teamClient` 时，会在团队页面提供公共云端服务的创建、加入入口，无需手动填写服务地址。公共服务地址为 `https://47.84.77.193/plugins/dsh-codex-shared-pool/team`。

尚未加入时，模型请求继续使用本地 Codex 账号池。创建或加入成功后，下一次请求开始使用 Team；断开本机连接后，下一次请求恢复使用本地账号池。已选择 Team 的请求遇到权限、限额或网络错误时，会保留该错误，不会自动借用本地账号完成请求。

明确配置的 `teamClient.enabled: false`、自建服务器地址和凭据名称继续生效。启用了 `team.enabled` 的 Team 服务端也不会自动成为公共云端客户端。

## 看到“Team 服务不可用”时

先看页面显示的服务地址。`127.0.0.1`、`localhost` 或 `::1` 都指向运行这台 DSH Host 的电脑；它们不会指向公共云端。此时应启动对应的本机测试服务，或由维护者把 Host 连接恢复到正确的云端服务。

如果显示的是正确的云端地址，检查该 Host 到服务的网络连接和服务运行状态，再点击重试。创建新团队或重新加入不能修复服务地址错误、断网或服务停机。网络错误本身不会清除已保存的成员凭据。

“团队访问已失效”与服务连接失败不同。只有确定原成员凭据已失效时，才清除本机连接并重新加入；所有者应使用原团队的恢复码恢复管理身份。

## 已经安装 0.1.4 的用户

npm 上已发布的 0.1.4 不会随 GitHub main 更新而改变。它已有创建、加入功能，但需要维护者先配置正确的 Team 服务地址。升级到 0.1.5 后，未配置的安装会默认提供公共云端入口；已有显式配置不会被覆盖。若旧配置指向已停止的 localhost 测试服务，需要删除该 `teamClient` 配置以使用云端默认值，或显式改为正确的云端地址并使用独立凭据名称。

已经连接云端并能正常使用的用户无需新建或重新加入。原团队、成员和共享账号继续留在原云端服务。

本机测试服务里的团队和邀请码只属于那台服务，不能直接转成云端团队。在云端新建团队会得到独立团队；其他成员需要使用它的新邀请码加入，需要共享的账号也要在新团队重新添加。

维护者为尚未连接云端的 0.1.4 安装配置公共服务时，可以在已有插件条目的 `config` 下使用：

```yaml
teamClient:
  enabled: true
  baseUrl: https://47.84.77.193/plugins/dsh-codex-shared-pool/team
  apiKeyRef: DSH_CODEX_SHARED_POOL_PUBLIC_CLOUD_API_KEY
```

这里使用独立凭据名称，避免把旧测试服务的成员密钥发到新地址。重启 DSH 后，在页面使用云端邀请码加入，或使用原云端团队的恢复码恢复所有者身份。若已有可用的云端连接，请保留原凭据配置。

默认云端入口同样使用按服务地址隔离的凭据名称，且不会自动迁移旧的通用 Team key 或未完成的加入、授权记录。自建服务的凭据始终保留在其原配置中。
