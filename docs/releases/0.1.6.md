# 0.1.6：团队邀请、共享授权与请求记录修复

`dsh-codex-shared-pool@0.1.6` 汇总已合并的团队体验修复，兼容官方 **DSH 0.1.2-rc.1 / Cordis 4.0.2**。

## 主要变化

- 团队成员可查看他人共享账号最近 1 天的请求次数和 API 等价金额，打开近 7 天内最新 10 条共享请求，查看消耗成员、模型、状态、时间及 Token 用量。只统计团队共享请求；修改共享设置仍仅限贡献者。
- 普通成员可查看已有可用邀请码；创建和撤销仍仅限所有者。入队入口先预览邀请，再确认加入。
- 首次共享使用浏览器实际授权的账号，可以与所选本机账号不同；已有本机账号绑定的浏览器重新授权仍校验该账号身份。
- 已退出、被移除或解散的团队会从本机保存连接中清理。
- 设置页隐藏团队服务器地址，简化本机账号标题和优先级展示。

## 安装与云端连接

```sh
npx @deepseek-ai/dsh@0.1.2-rc.1 plugin --profile web add dsh-codex-shared-pool@0.1.6
npx @deepseek-ai/dsh@0.1.2-rc.1 web
```

升级前备份 DSH 数据并退出旧进程，随后启动原 Web profile。全新安装继续使用现有 HTTPS 公共云端入口，无需填写服务地址；已有显式地址、禁用设置及凭据配置保持不变。原本正常的云端团队无需重建或重新加入。

成员查看邀请码和共享账号请求数据需要团队服务端同步升级。发布 npm 包和 GitHub Release 不会自动部署正在运行的云端 Host/Broker。旧服务端缺少共享请求数据时，页面显示最近 1 天用量暂不可用，并禁用近 7 天按钮；这不代表零次请求。

若旧配置显式指向 `localhost`、`127.0.0.1` 或 `::1`，这些地址仍指向运行 DSH 的电脑，需要维护者核对 Host 配置。设置页不再展示服务地址；详细恢复步骤见 [团队连接与恢复](https://github.com/502399493zjw-lgtm/dsh-codex-shared-pool/blob/main/docs/team-connection.md)。

## 验证范围

相关修复已有单元、DOM 与 CI 回归覆盖；CI 包括真实 PostgreSQL 并发、Docker 多团队隔离，以及 Linux/Windows 的官方 DSH 安装验证。发布包另行执行构建、包格式校验和隔离 stock DSH 安装验证。

已有本地真实页面验证覆盖当前贡献者账号的 1 天统计和 7 天明细；它不能证明普通成员在远端团队服务上的新权限已生效。本次版本不把历史真实 OAuth 记录作为新的授权验收。README 中的截图和 GIF 仍是明确标注的 `0.1.4` 历史素材。
